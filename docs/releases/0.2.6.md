# Claude++ 0.2.6

Claude++ 0.2.6 adds a Main Tweak API for in-process MCP servers and an explicit-ID session-title capability for
supported Claude Desktop builds.

## Added

- Main-only `mcp` permission and `api.mcp.registerServer(...)` for handler-backed SDK MCP servers.
- Main-only `claude-session-title-write` permission and
  `api.claude.sessionTitles.setTitle(sessionId, title)` for a known Desktop session.
- Process-wide structural validation, collision rejection, handler revocation, registration leases, and active-session
  reconciliation across Tweak stop, disable, and hot reload.
- The independent [Claude Session Title Tweak](https://github.com/kpkhxlgy0/claude-session-title), which exposes an
  explicit `set_session_title(session_id, title)` MCP tool for Claude Desktop. The Tweak is distributed separately and
  does not add a tool to terminal-launched Claude Code.

## Compatibility and lifecycle

- Runtime 0.2.6 initially supported Claude Desktop app version `1.26832.0` and also supports app version `1.32885.1`,
  which corresponds to Windows MSIX version `1.32885.1.0`. Each build has its own exact private-boundary record:
  Desktop app version, four bundled-module SHA-256 hashes, export slots, and required runtime shapes must all match.
- An unsupported version, hash, or shape fails closed. Claude continues to start, Claude++ injects no custom MCP
  server, and there is no configuration-writing or alternate-private-path fallback.
- A registration is owned by its Main Tweak API lease. Unregistering or disposing that lease revokes handlers before
  Desktop sessions reconcile their server list.
- A server's name and version plus its tool names, descriptions, and schemas are immutable for one Desktop process.
  Same-owner hot reload may replace handler functions only when the complete structural definition is unchanged.
- Both new permissions are Main-only capability declarations. They control which Claude++ APIs are exposed but do not
  place trusted Main Tweak JavaScript in an operating-system sandbox.

## Configuration and persistence

MCP injection is entirely in memory. Claude++ does not write `~/.claude.json`, project `.mcp.json`, Claude
`settings.json`, or an MCP managed block, and it does not patch the Desktop ASAR. A successful title change still uses
Claude Desktop's normal user-title persistence path so the session metadata and transcript title survive restart.

This intentionally differs from Codex++, whose `manifest.mcp` declares external `command`/`args`/`env` servers and
whose Runtime synchronizes them into `~/.codex/config.toml`. The in-process Claude++ design is the approved tradeoff
needed to preserve the no-configuration-write requirement; it is Desktop-only and must be reviewed when Desktop's
private implementation changes.

## Install

Download `claude-plusplus-0.2.6-win-x64.zip`, extract it, and run:

```powershell
.\install.ps1
```

Existing installations can run the same installer for routine maintenance. Claude++ preserves configuration, Tweak
Junctions, Tweak data, Safe Mode, enabled flags, and old managed mirrors.
