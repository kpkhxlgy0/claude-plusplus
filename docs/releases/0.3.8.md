# Claude++ 0.3.8

Claude++ 0.3.8 restores its Settings navigation after Claude changes the native sidebar labels.

## Fixes

- Recognize Settings rows by their stable identifiers so Config, Tweaks, and Tweak Store appear with
  the new `Appearance` and `Code` labels and their translations.
- Use the native Account row when the capability-dependent Code row is absent, while retaining the older English-label
  fallback for previous Claude Settings layouts.
- Restore the native Settings panel when switching back from a Claude++ page.

## Install or update

Fully quit Claude before updating. Download `claude-plusplus-0.3.8-win-x64.zip` and its `.sha256` checksum from the
[release page](https://github.com/kpkhxlgy0/claude-plusplus/releases/tag/v0.3.8), extract the ZIP, and run `install.ps1`.
Then run `bin\claudeplusplus.cmd doctor` and open the **Claude++** Start Menu shortcut.

For a local Git checkout, install Node.js 24+ with npm, update the checkout with Git, and run its saved `install.ps1`.

Keep the official Claude Store package installed. Use the Claude++ shortcut or `bin\claudeplusplus.cmd launch`
to retain the registered Windows package identity.

## Verification

- All 768 automated tests passed, with zero failures or skips, including the SDK, Runtime, Installer, and Loader builds.
- Settings regression coverage includes renamed and translated labels, the missing Code row, native content restoration,
  older layouts, and rejection of dialogs without recognized native Settings identifiers.
- The Windows archive passed checksum verification and isolated portable-CLI version, status, Doctor, and Tweak
  authoring checks without system Node.js or npm on PATH. The package smoke also rejected an external-target Junction
  and preserved its sentinel during cleanup.
- PowerShell syntax and Git whitespace checks passed. Windows package verification used disposable profiles.

## Known dependency warning

Packaging reported six vulnerabilities (three moderate and three high) for the complete build dependency tree and four
(three moderate and one high) for the production-only package dependency tree.
